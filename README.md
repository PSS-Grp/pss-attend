# pss-attend

葬儀会館スタッフ向けの勤怠管理（出退勤打刻）・手配書共有アプリです。Flask製で、
[Render](https://render.com) にBlueprint（`render.yaml`）を使ってそのままデプロイできます。

## できること

- 一般の従業員アカウントでログインし、本葬・通夜それぞれの出勤・退勤を打刻できます。
- 打刻後もハブ画面（`/judge`）から続けて操作でき、本葬・通夜は互いの状態
  （通夜の後に本葬はできない、本葬出勤中は通夜を開始できない、など）に応じて
  ボタンが自動的に押せなくなります。
- 自分の勤怠記録を月ごとに一覧表示できます（`/attendance_list`）。
- 「手配者」専用アカウントが、一般従業員・本葬/通夜・日付を指定して画像とメモ
  （本日の手配書）を登録でき、対象の従業員だけがログイン後の「本日の手配書」
  ボタンから、自分宛て・当日分の内容を確認できます。
- 管理者アカウントは `/admin` から従業員・会館名・勤怠記録・手配書を
  閲覧/編集でき、勤怠記録は従業員ごとにCSV出力できます。

## リポジトリ構成

```
.
├── attendance_fixed/     # アプリ本体（Flask）
│   ├── __init__.py       # アプリ初期化・DB設定・シークレットキー
│   ├── index.py          # ログイン・ハブ画面・勤怠一覧などのルート
│   ├── honso.py          # 本葬の出退勤
│   ├── tsuya.py          # 通夜の出退勤
│   ├── arrangement.py    # 手配書機能（登録画面・本日の手配書画面・画像配信）
│   ├── admin.py          # データベース管理画面（Flask-Admin）
│   ├── models.py         # DBモデル（User / Time / Place / Arrangement）
│   ├── seed_demo_user.py # 動作確認用デモアカウント・サンプルデータの作成
│   ├── requirements.txt  # 依存パッケージ
│   └── templates/, static/
├── wsgi.py               # 本番(gunicorn)用エントリポイント
├── render.yaml           # Render Blueprint定義
├── .python-version       # Renderで使うPythonバージョンの指定
└── smoke_test.py         # Flaskのテストクライアントによる自動テスト
```

## Renderへのデプロイ

1. このリポジトリをフォーク、またはRenderの自分のアカウントに接続します。
2. Renderのダッシュボードで「New +」→「Blueprint」を選び、このリポジトリを選択します。
3. `render.yaml` の内容に従って、Webサービスと永続ディスク（1GB、`/var/data`に
   マウント）が自動的に作成されます。`ATTENDANCE_SECRET_KEY` は初回デプロイ時に
   Renderが安全な値を自動生成します。
4. デプロイが完了すると、起動時に `wsgi.py` が動作確認用のデモアカウント・
   サンプルデータを自動作成します（`seed_demo_user.py` 参照。既に存在する
   データは重複作成しないので、再デプロイ・再起動のたびに実行しても安全です）。

### デモアカウント

| 用途 | 従業員番号 | パスワード |
| --- | --- | --- |
| 一般従業員（出退勤打刻） | `0001` / `0002` / `0003` | `demo1234` / `demo2345` / `demo3456` |
| 管理者（`/admin`） | `9001` | `admin1234` |
| 手配者（`/arrangement_manage`） | `7001` | `staff1234` |

これらは動作確認用の固定パスワードです。実際の運用で公開する場合は、
`/admin/user/` から専用のアカウントを作成し、デモアカウントは無効化・
削除することを推奨します。

### データの永続化について

勤怠記録・手配書のデータと、手配書のアップロード画像はSQLiteファイルとして、
環境変数 `ATTENDANCE_DATA_DIR`（`render.yaml`では永続ディスクのマウント先
`/var/data`を指定）配下に保存されます。この環境変数が未設定の場合は、
アプリのコードと同じ場所に保存されます（ローカルでの動作確認用）。

永続ディスクはRenderの有料プランでのみ利用でき、1サービスにつき1つ・
1インスタンスからのみアクセスできるため、このサービスは複数インスタンスへの
自動スケールはできません（アプリの利用規模であれば通常問題ありません）。

## ローカルでの動作確認

```bash
pip install -r attendance_fixed/requirements.txt
python wsgi.py  # http://127.0.0.1:5000/login
```

## テスト

Flaskのテストクライアントを使った一連の自動テスト（ログイン・出退勤の
状態遷移・データ分離・管理画面のアクセス制御・手配書機能など）を用意しています。

```bash
python smoke_test.py
```
